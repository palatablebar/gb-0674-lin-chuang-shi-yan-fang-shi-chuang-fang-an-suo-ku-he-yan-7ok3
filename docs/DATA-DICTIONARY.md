# 访视与冻结定义

样例均为虚构编号，无身份信息。受试者入组日期由subjects表唯一确定，记录中的入组基准必须完全一致。采样日期和入组日期均转为Asia/Shanghai日历日期，差值为访视日；时刻先统一UTC。
方案选择按当前受试者assignment和该次发生时刻查半开生效窗，匹配必须唯一，不能使用全局最新方案。v1访视V1=[5,10)、V2=[12,17)；v2为[6,11)、[13,18)。受试者00001于10月10日转v2，其他受试者仍用v1。
PRIMARY计入访视完成，RETEST只替代该次测量值。首次记录必须唯一且在访视窗内。缺首次访视、重复首次和窗外访视均阻断，复检不能填补漏访或消除原偏离。
复检须引用同受试者同访视的PRIMARY，晚于原采样且不超过72小时，版本必须更高。同最高版本复检冲突时保留原结果并阻断。所有检验值以mg/dL输出，g/L乘100。
锁库须所有规定访视完成，无偏离、复检问题和隔离行。冻结包包含每条选定结果、原始行号、方案版本与访视窗。此工具只验证试验数据完整性，不做诊断判断或生产锁库。

## 统一截止口径与晚到裁决

锁库截止点固定为 `2026-11-20T18:00:00+08:00`（Asia/Shanghai），方案版本、访视窗、锁库闸门、冻结凭证、锁库登记共用同一 `context.cutoff` 对象，不允许各模块各取一个时间。

- 每条记录携带两个时间：现场采样时刻 `at`（event_field）与系统接收时刻 `received_at`（basis_field），另有录入方式 `entry_mode`（LIVE/BACKFILL）。
- 唯一纳入判据是 **系统接收时刻 `received_at` ≤ 截止点**；`at` 只用于计算访视窗，不决定能否进入本次锁库。这避免"按现场时间纳入会带进截止后才知的结果"。
- 接收时刻晚于截止点的记录一律暂缓（HOLD），不论采样发生在何时：
  - `LATE_RECEIPT_COMPLETED`：访视截止前已完成、记录晚到；
  - `LATE_BACKFILL_EARLIER`：补录更晚却指向更早采样，不能冒充截止前数据；
  - `LATE_AFTER_EVENT`：采样与接收均在截止后。
- 截止点前接收的记录纳入：`ON_TIME_RECEIPT`、`ON_TIME_BACKFILL`；旧批无接收时刻列时按采样时刻视同在册并标注 `LEGACY_RECEIPT_DEFAULT`，不静默处理。
- 暂缓不是丢弃：晚到记录连同原始行号、两个时间、原因码进入 `late_register`，随批次持久化并出现在冻结凭证中，留待下一版冻结；本次正式锁库不引用这些结果。
- 行守恒扩展为：输入行 = 采纳行 + 隔离行 + 晚到暂缓行 + 空行 + 同值重复 + 重复表头。

## 正式锁库与不可覆盖

- 封存只接受闸门状态为"可锁库"的批次；存在晚到暂缓或其他阻断项时拒绝封存（`LOCK_NOT_READY`）。
- `formal_locks` 与 `audit_log` 为仅追加表，SQLite 触发器拒绝任何 UPDATE/DELETE。
- 正式快照指纹只由不可变输入快照、规则版本与统一截止口径决定；截止后到达的补录不在快照内，无法改变指纹，因而不能覆盖正式结果。
- 同批重跑读取封存快照重新计算，只做校验：指纹一致记 `UNCHANGED`；不一致或重算异常时保留旧版、追加 `FAILED`/`MISMATCH` 记录，绝不改写封存行。
- 审计为哈希链，每条含前序哈希与本条哈希，可通过 `GET /api/audit` 校验完整性。
- 原始记录可追溯：运行导出包含 `input_snapshot.json`、`cutoff_policy.json`、逐记录 `timing_decisions` 与 `late_register`；锁库证书另含 `lock_certificate.json`。
