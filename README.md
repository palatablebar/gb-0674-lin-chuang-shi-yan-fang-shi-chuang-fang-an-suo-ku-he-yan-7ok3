# 临床试验访视窗与方案锁库核验

给临床试验数据管理员使用。按入组基准计算访视半开窗，方案修订按受试者生效时间选版；漏访不可用复检伪填。锁库以系统接收时刻为唯一纳入判据，晚到记录暂缓留痕、不覆盖正式结果。

九个业务模块：记录采信、截止裁决、方案版本、访视排窗、偏离复核、复检裁决、锁库检查、冻结归档、锁库登记。

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
```

访问 http://localhost:18243 。启动直接载入现场脏批。切换完整样例、晚到样例和旧编码样例可对照核验。清批20个虚构受试者、40次应访视及5次复检，可锁库冻结。晚到批（late）含两条关键记录：访视截止前已完成却晚到的 `00001-V1`，以及更晚补录却指向更早采样的 `00002-V1`，二者按接收口径进入暂缓区并阻断封存。现场脏批包含窗末偏离、缺首次访视、错误复检引用及方案不符，必须处理后才能冻结。

## 截止口径（方案/访视窗/锁库/冻结/登记共用）

锁库截止点固定 `2026-11-20T18:00:00+08:00`，由 `app/config.py` 的 `CUTOFF_POLICY` 注入同一 `context.cutoff` 对象。唯一纳入判据是系统接收时刻 `received_at ≤ 截止点`；现场采样时刻 `at` 只用于访视窗。接收晚于截止的记录一律暂缓（含补录指向更早采样），在"截止裁决"页可看清每条记录的现场时间、接收时间、采用时间以及纳入/暂缓原因码。旧批无接收时刻列时按采样时刻视同在册并显式标注。

## 正式锁库的不可覆盖保证

"锁库登记"页可把可锁库批次封存为正式锁库：

- `formal_locks`、`audit_log` 为仅追加表，SQLite 触发器拒绝 UPDATE/DELETE；
- 快照指纹只由不可变输入快照、规则版本与截止口径决定，截止后补录不在快照内，无法覆盖正式结果；
- 同批重跑只做校验：一致记 `UNCHANGED`；重算失败或不一致保留旧版并追加留痕，不改写封存行；
- 审计为哈希链，`GET /api/audit` 校验完整性；锁库证书 `GET /api/locks/{lock_no}/certificate` 下载。

各模块页面对应 `/<模块英文名>`，各模块执行入口为 `POST /api/<模块英文名>`，不传参即可独立演示。完整运行 `POST /api/runs` 支持 `dataset`（dirty/clean/late/legacy）、`csv_text` 与 `overrides` 参数。批次历史 `GET /api/runs`，详情 `GET /api/runs/{run_id}`。

同输入与规则版本生成相同批号，只保留一条批次。复核入口 `POST /api/runs/{run_id}/review` 提交当前 `revision`，陈旧提交409。归档包只有一个下载入口 `GET /api/export/{run_id}`，含截止口径、逐记录时间裁决、晚到暂缓清单、不可变输入快照和运行摘要。原始隔离与暂缓在页面同屏显示。

SQLite使用命名卷，容器重启后保留历史。要重建演示可在Compose中改用新的卷名称，保留旧卷。

源码在 `app/`，样例在 `sample_data/`，测试在 `tests/`；定义见 `docs/DATA-DICTIONARY.md`，模块和边界测试对应关系见 `docs/DEPTH.md`。输入上限2MB，属于离线复核工具。

采信页支持上传或粘贴CSV（尾列 `received_at,entry_mode` 可选，缺省按旧批处理）。完整源字节与参数随批次持久化，跨页通过run_id读取同一结果。`POST /api/runs/{run_id}/rerun` 读取该批不可变输入快照重新计算，规则未变时批号不变。切换另一示例则创建或复用另一批次。
